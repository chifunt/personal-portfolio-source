# Procedural background

The background runs a Gray-Scott reaction-diffusion simulation with gentle advection. Each page load chooses a seed with `crypto.getRandomValues`; navigation and resizing retain that visit's seed. The seed controls initial strands and patches, the parameter sequence, small disturbances, and drift direction. A fixed seed still reproduces a run for testing.

The two concentration fields spread and react through a normalized nine-point Laplacian, synchronous updates, and periodic boundaries. Feed/kill targets move smoothly between five pairs: (0.024, 0.054), (0.029, 0.057), (0.030, 0.062), (0.042, 0.063), and (0.054, 0.062). Transitions last 800 to 1,800 simulation steps, with a small spatial variation across the field. A weak circulating flow bends the strands; occasional soft, local pulses grow or open a patch without resetting the whole pattern. These are visual choices for the site, not the thesis evaluation model. The reaction terms follow the [Gray-Scott model](https://groups.csail.mit.edu/mac/projects/amorphous/GrayScott/).

## Runtime budget

- Desktop uses a 160 by 160 grid with a rendering cap of 12 frames per second.
- Phones and devices with a coarse pointer use a 112 by 112 grid with a cap of 8 frames per second.
- Both target 192 simulation steps per second, with a six-millisecond computation budget per frame. Slower devices take fewer steps. Timers never catch up after a pause or a busy frame.
- A worker computes the fields and an alpha mask. Canvas 2D repeats that mask in 320-pixel tiles and colours the contours with Love, Gold, Rose, Foam, and Iris from the site's Rose Pine palette.
- The display canvas uses half the viewport resolution, capped at 1024 pixels on its longest side. Smaller patterns do not require a larger simulation grid.
- The worker transfers and reuses one pixel buffer. It does not queue more frames while the page is drawing the previous one.
- Initialization runs in short batches so a visibility or pause message can interrupt it.
- Hidden tabs pause every ambient animation. Reduced-motion preferences start with a static pattern without starting a worker. Visitors can opt into animation with the navbar control.
- The navbar's labelled play/pause icon controls the pattern, matrix rain, gears, portrait glitch, name gradient, placeholder gears, and button glow. The choice survives navigation and reloads. CSS animations freeze in place; the canvas loops and worker stop scheduling work.

The effect adds no dependencies. A 13 KB WebP mask generated by the same simulation appears before the worker is ready and when a worker cannot run. Periodic boundaries allow the field to repeat across the viewport. Resizing within a device category does not restart the simulation.

The pattern sits behind all page layers at 8% opacity. Gears and Chinese lettering use opaque colours mixed with the base colour, so the pattern cannot show through their shapes. Its colours tint the contours. Drift follows a gently bending path at three to five pixels per animation second, with a direction and speed chosen by the visit's seed. Its clock advances only on rendered frames, independently of the number of simulation steps the device can afford. Evolution and drift both stop when paused.

## Files

- `lib/reaction-diffusion.ts` contains the model and contour mask.
- `lib/reaction-diffusion.worker.ts` owns the timer and pixel buffer.
- `components/procedural-background.tsx` connects the canvas and shared motion state.
- `components/site-motion.tsx` owns the motion preference, page visibility, and shared pause state.
- `app/globals.css` sets the tile size, background opacity, fallback colours, stacking, and CSS animation pause rules.

Regenerate the static pattern after changing the model or colours:

```sh
node --experimental-strip-types scripts/generate-reaction-diffusion-poster.mjs
```

Run the numerical checks:

```sh
node --experimental-strip-types --test tests/reaction-diffusion.test.mjs
```

The checks cover the resting state, border wrapping, synchronous updates, reproducibility across parameter changes and pulses, different evolution from different seeds, ten-minute runs without uniform or frozen fields, and rendered changes over five seconds on both device grids.

Simulation timing alone excludes worker messaging and browser compositing. Measure the complete page when assessing performance on a target device.
